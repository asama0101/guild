# guild

依頼を Todo に分解し、自動でできるものは自動で、あなたの作業が要るものはその結果を待って、納品まで進める Claude Code プラグインです。個人利用を前提にしています。質問・承認・結果の入力は、チャットではなく**ボード**（ブラウザで開く 1 ファイルの HTML）で行います。役名や画面の呼び名は、RPG のギルドにならっています。

## guild でできること

- **依頼を分解して進める**: 依頼を Todo に分け、Claude が自動で実行するもの（`auto`）と、あなたが実行して結果を返すもの（`human`）に分けます。承認は、計画の 1 回だけです。
- **合格基準で判定する**: 各 Todo に合格基準を付け、満たさなければ実行に戻します。
- **資料と知識を使い回す**: 依頼で使う資料（**インプット**）を共通の置き場に 1 つだけ置いて使い回します。用語・業務フロー・業務情報などは**書庫**に溜まり、次の依頼で全員が使います。
- **ボードで見る**: 進み具合、あなたへの質問（**手紙**）、納品物、日付のガントチャートを、ひとつの画面で見られます。
- **成果物は Markdown**: PowerPoint や Excel が要るときは、Claude Code に貼るプロンプトを Markdown で渡します。

## 動かすのに必要なもの

- Claude Code
- Python 3（`/guild:init` が `py`、`python3`、`python` の順に探します）
- Chrome または Edge（ボードを開くため。Firefox と Safari は使えません）
- Playwright MCP（`playwright` という名前で導入・接続しておく。未接続だと `/guild:init` が警告して止まります）

## インストール

このリポジトリをマーケットプレイスとして追加し、プラグインを入れます。

```
/plugin marketplace add <このリポジトリのパス>
/plugin install guild@guild-local
```

## 最初の依頼を出すまで

1. 作業するプロジェクトのフォルダで、Claude Code から `/guild:init` を実行します。`guild/` ができます。何度実行しても、依頼や書庫の項目は消えません（`guild/board.html` は新しい版に置き換わります）。
2. `guild/board.html` を Chrome か Edge で開き、「フォルダを選ぶ」でプロジェクトのフォルダ（`guild/` の 1 つ上）を選びます。
3. 「＋ 新規」で依頼を書きます。使う資料があれば、インプットとして既存から選ぶか、アップロードします。チャットから出すときは `/guild:quest <依頼文>` です。
4. Claude Code で `/guild:quest` を動かしておきます。計画ができたらボードの「手紙」に承認の確認が出るので、答えます。以降は、質問や、あなたの実行（`human` の Todo）が要るときだけ手紙が届きます。ボードに答えた内容は、動いている `/guild:quest` が受け取って続きを進めます。
5. 全 Todo が済むと「受け取りの確認」の手紙が出ます。受け取ると完了で、納品物（Markdown）が `guild/deliverables/Q###_….md` に置かれます。

| コマンド | 内容 |
|---|---|
| `/guild:init` | 現在のフォルダに `guild/` を作り、使える Python を記録する |
| `/guild:quest` | 依頼の分解・実行・判定・納品までを進める（ギルドマスター） |

## 依頼が納品されるまでの流れ

```
依頼 → 分解（地図師）→ 承認（1回）→ 実行（冒険者・斥候 / あなた）→ 合否（鑑定士）→ 記録（司書）→ 納品
```

進め方（Todo の依存関係と状態遷移）は文章ではなくデータで持ち、`guild.py` が辿ります。役は作業と報告だけをして、順序・合否・リトライは判断しません。詳しくは [docs/spec.md](docs/spec.md) と [docs/graph-format.md](docs/graph-format.md) を参照してください。

## 資料・成果物・知識の扱い

### 資料を渡す（インプット）

依頼で使う資料は `guild/inputs/` に 1 つだけ置き、各クエストは名前で参照します。

- 同じ名前でアップロードすると上書きされます。古い版は、そのクエストが閉じるまでバックアップが残ります。
- 地図師が、依頼文と書庫のヒントから、関係するインプットを理由つきで選びます。「＋ 新規」であなたが選んだものは、必ず入ります。
- 承認の前でも後でも、クエストの詳細の「インプット」タブで、外す・追加する・既存から選ぶ・ファイルをアップロードする、ができます（タブからのアップロードは、同名のファイルがあると置けません。上書きは「＋ 新規」から）。
- 納品物の型（見出しの並びなど）は、型にしたいファイルをインプットに付けて、依頼文で伝えます。

### 成果物を受け取る（納品物）

納品物は Markdown です。PowerPoint や Excel などが要るときは、Claude Code に貼って使うプロンプト（`*.prompt.md`）が一緒に置かれます。

### 知識を溜めて使い回す（書庫）

用語・業務フロー・業務情報・個人・心得が溜まります。依頼が完了または中止になると、司書が登録候補を挙げ、あなたが選んだものだけが登録されます。`guild/` を Obsidian の Vault にすると、書庫・納品物・インプットを読めます（作業用の `.work/` は出ません）。仕様は [docs/archive-spec.md](docs/archive-spec.md) です。

### 外部サイトを開くとき（許可制）

冒険者が WebFetch で開けるのは、あなたが許可したドメインだけです。許可のないサイトはフックが止め、ボードの手紙で「許可リストに加える／今回だけ／許可しない」を聞きます。ボード自体は外部と通信しません。データはすべて、プロジェクトの `guild/` の中にあります。

## ボードの見方

タブは次のとおりです。操作の手順は、ボードの「ヘルプ」にあります。設計は [docs/board-design.md](docs/board-design.md) です。

| タブ | 内容 |
|---|---|
| クエスト掲示板 | 左にクエストの一覧（隠せる）、右に選んだクエストの詳細。詳細に手紙と、道のり／日付／インプットのタブがある。「＋ 新規」でクエストを出す |
| クエスト進捗 | 選んだクエストの開始日〜締切のガントチャートと、Todo の予定日、あなたの実行の日ごとの件数 |
| 納品物 | 受け取った納品物とプロンプトの一覧とコピー |
| 書庫 | 閲覧・検索・登録・編集。項目にインプットを紐づけられる |
| 外部サイト | 開けるサイトの許可リスト |
| Obsidian | Obsidian で読む手順 |
| ヘルプ | 処理フローの図、役の説明、使い方、困ったとき |

## ギルドの顔ぶれ（役）

| 役 | 名前 | やること |
|---|---|---|
| ギルドマスター | `/guild:quest` 本体 | 依頼の受け付け、`guild.py` の実行、役の呼び出し、ボードの答えの待機 |
| 地図師 | `cartographer` | 依頼を Todo に分解し、種別・合格基準・使うインプットを決める |
| 冒険者 | `adventurer` | `auto` の Todo を実行し、報告と成果物を書く |
| 斥候 | `scout` | ブラウザで動的ページを読む（読むだけ） |
| 鑑定士 | `appraiser` | 成果物を合格基準で判定する（成果物は直さない） |
| 司書 | `librarian` | 書庫に残す候補を挙げる（登録はしない） |

モデルなど役の詳細は [docs/roles-spec.md](docs/roles-spec.md) です。

## ファイルはどこにできるか

```
guild/
  config.json     設定（Python のパスなど）
  board.html      ボード
  archive/        書庫
  deliverables/   納品物とプロンプト（Q001_….md / .prompt.md）
  inputs/         共通のインプット
  .work/          作業用（依頼ごとのフォルダなど。Obsidian には出ない）
```

## つまずいたとき

- **`/guild:init` が「Playwright MCP が見つかりません」で止まる**: `playwright` という名前で MCP を導入・接続してから、もう一度実行します。`guild/` はこの時点では作られません。
- **Python が見つからない**: Windows では、`python` がストアへの誘導だけで動かないことがあります。`py` か `python3` で動く Python 3 を入れてください。
- **`/guild:quest` が「/guild:init を先に」と止まる**: そのフォルダで `/guild:init` を実行します。
- **ボードで答えたのに進まない**: ボードの答えを受け取って進めるのは、動いている `/guild:quest` です。止まっていたら、もう一度 `/guild:quest` を実行すると、続きから進みます。
- **ボードが「フォルダを選ぶ」から先に進まない**: Chrome か Edge で開き、`guild/` の 1 つ上のフォルダを選びます。
- **納品物が `guild/deliverables/` にない**: `/guild:quest` に、納品物を置き直すよう伝えます（`guild.py publish`）。

## 開発する人へ

構成:

- `skills/` — `init`、`quest`（`guild.py`、`webaccess.py`、`board.html`、`transitions.json`）
- `agents/` — 各役の指示書
- `hooks/` — 冒険者の WebFetch を許可リストで判定するフック
- `docs/` — 設計の文書
- `tests/` — テスト

テストは次で実行します。

```
python -m unittest discover -s tests
```
