# guild

依頼を目標に分解し、自動でできるものは自動で、あなたの作業が要るものはその結果を待って、納品まで進める Claude Code プラグインです。個人利用を前提にしています。質問・承認・結果の入力は、チャットではなく**ボード**（ブラウザで開く 1 ファイルの HTML）で行います。役名や画面の呼び名は、RPG のギルドにならっています。

## guild でできること

- **依頼を分解して進める**: 依頼を目標に分け、Claude が自動で実行するもの（`auto`）と、あなたが実行して結果を返すもの（`human`）に分けます。承認は、計画の 1 回だけです。承認の手紙には、依頼の理解（言い換え）・含めないこと・推測で決めた前提・うまくいかないかもしれないこと・要件と目標の対応・計画の警告・あなたの作業量が出るので、そこを見て判断できます（直すときは差分も出ます）。
- **合格基準で判定する**: 各目標に合格基準を付け、満たさなければ実行に戻します。
- **資料と知識を使い回す**: 依頼で使う資料（**インプット**）を共通の置き場に 1 つだけ置いて使い回します。用語・業務フロー・業務情報などは**書庫**に溜まり、次の依頼で全員が使います。
- **ボードで見る**: 進み具合、あなたへの質問（**手紙**）、納品物・成果物・報告などのファイル（「納品物」タブ）、日付のガントチャートを、ひとつの画面で見られます。
- **成果物は Markdown**: PowerPoint や Excel が要るときは、Claude Code に貼るプロンプトを Markdown で渡します。

## 動かすのに必要なもの

- Claude Code
- Python 3（`/guild:init` が `py`、`python3`、`python` の順に探します）
- Chrome または Edge（ボードを開くため。Firefox と Safari は使えません）
- Playwright MCP（`playwright` という名前で導入・接続しておく。未接続だと `/guild:init` が警告して止まります）

## インストール

このリポジトリをマーケットプレイスとして追加し、プラグインを入れます。

```
/plugin marketplace add <このリポジトリのパス>
/plugin install guild@guild-local
```

## 最初の依頼を出すまで

1. 作業するプロジェクトのフォルダで、Claude Code から `/guild:init` を実行します。`guild/` ができます。何度実行しても、依頼や書庫の項目は消えません（`guild/board.html` は新しい版に置き換わります）。
2. `guild/board.html` を Chrome か Edge で開き、「フォルダを選ぶ」でプロジェクトのフォルダ（`guild/` の 1 つ上）を選びます。
3. 「＋ 新規」で依頼を書きます。使う資料があれば、インプットとして既存から選ぶか、アップロードします。チャットから出すときは `/guild:quest <依頼文>` です。
4. Claude Code で `/guild:quest` を動かしておきます。計画ができたらボードの「手紙」に承認の確認が出るので、答えます。以降は、質問や、あなたの実行（`human` の目標）が要るときだけ手紙が届きます。ボードに答えた内容は、動いている `/guild:quest` が受け取って続きを進めます。
5. 全目標が済むと「受け取りの確認」の手紙が出ます。受け取ると完了で、納品物（Markdown）が `guild/deliverables/Q###_….md` に置かれます。
6. ボードの上に「/guild:quest：待機中／作業中／停止中」が出ます。「停止中」のときは、ボードで答えても動かすまで拾われません。「あなたの番」が増えると、タブの題に件数（例：(1) guild 依頼掲示板）が出ます。止まっている目標には、道のりに「止まっている原因」が出ます。
7. 業務終了時は、ボードの「ギルドを閉める」か `/guild:close` で止めます。依頼は中止になりません。翌日は `/guild:quest` を実行すると、続きから進みます。

| コマンド | 内容 |
|---|---|
| `/guild:init` | 現在のフォルダに `guild/` を作り、使える Python を記録する |
| `/guild:quest` | 依頼の分解・実行・判定・納品までを進める（ギルドマスター） |
| `/guild:close` | ギルドを閉める。新しい作業を始めず、実行中の作業が終わったら止まる（依頼は中止にならない）。ボードの「ギルドを閉める」ボタンでも同じ |

## 依頼が納品されるまでの流れ

```
依頼 → 分解（受付係）→ 承認（1回）→ 実行（魔法使い・錬金術師・冒険者 / あなた）→ 合否（鑑定士）→ 総合確認（受付係）→ 受け取り（あなた）→ 記録（司書）
```

- **確認の印の抜けを防ぐ**: 受付係は、実行する目標ごとに影響（`effects`：なし／外部への送信・公開／元に戻せない変更）を宣言します。外部・不可逆の目標に確認の印がない計画は、受け付けません。承認の手紙に出ます。
- **総合確認**: 全目標が合格したら、受付係が、依頼文と納品物だけを読んで、要件を満たしているかを照合します。不足があれば、受け取りの手紙に出ます（自動では直しません。受け取るか、直してほしいかは、あなたが決めます）。
- **納品物の置き場**: 依頼文に置き場の指定があれば、受け取ったときに、プロジェクトの指定のフォルダ（`guild/` の外の、プロジェクト内）にもコピーします。承認の手紙に出ます。

進め方（目標の依存関係と状態遷移）は文章ではなくデータで持ち、`guild.py` が辿ります。役は作業と報告だけをして、順序・合否・リトライは判断しません。詳しくは [docs/spec.md](docs/spec.md) と [docs/graph-format.md](docs/graph-format.md) を参照してください。

## 資料・成果物・知識の扱い

### 資料を渡す（インプット）

依頼で使う資料は `guild/inputs/` に 1 つだけ置き、各クエストは名前で参照します。

- 同じ名前でアップロードすると上書きされます。古い版は、そのクエストが閉じるまでバックアップが残ります。
- 受付係が、依頼文と書庫のヒントから、関係するインプットを理由つきで選びます。「＋ 新規」であなたが選んだものは、必ず入ります。
- 承認の前でも後でも、クエストの詳細の「インプット」タブで、外す・追加する・既存から選ぶ・ファイルをアップロードする、ができます（タブからのアップロードは、同名のファイルがあると置けません。上書きは「＋ 新規」から）。
- 納品物の型（見出しの並びなど）は、型にしたいファイルをインプットに付けて、依頼文で伝えます。

### 成果物を受け取る（納品物）

納品物は Markdown です。PowerPoint や Excel などが要るときは、Claude Code に貼って使うプロンプト（`*.prompt.md`）が一緒に置かれます。

### 知識を溜めて使い回す（書庫）

用語・業務フロー・業務情報・個人・心得が溜まります。依頼が完了または中止になると、司書が登録候補を挙げます。出典のあるものと心得は、そのまま登録されます。推測のものと、既存の項目との食い違いだけ、あなたが選びます（ボードからいつでも追加・編集・削除もできます）。同じ心得が 2 回出ると、司書が「掟に足してはどうか」と提案し、あなたが採用したものだけが、プロジェクトの掟に足されます。魔法使い・錬金術師・冒険者は、作業のたびに経験のメモを残し、司書が職業ごとの要約にまとめます（`guild/.work/experience/`）。次の依頼で、各役が作業の前に読みます。`guild/` を Obsidian の Vault にすると、書庫・納品物・インプットを読めます（作業用の `.work/` は出ません）。仕様は [docs/archive-spec.md](docs/archive-spec.md) です。

### 外部サイトを開くとき（許可制）

魔法使いが WebFetch で開けるのは、あなたが許可したドメインだけです。許可のないサイトはフックが止め、ボードの手紙で「許可リストに加える／今回だけ／許可しない」を聞きます（親ドメインごとに折りたたんで1行にまとめ、全部まとめて選ぶことも、各サイトの確認リンクを開くこともできます）。ボード自体は外部と通信しません。データはすべて、プロジェクトの `guild/` の中にあります。

## ボードの見方

タブは次のとおりです。操作の手順は、ボードの「ヘルプ」にあります。設計は [docs/board-design.md](docs/board-design.md) です。

| タブ | 内容 |
|---|---|
| クエスト掲示板 | 左にクエストの一覧（隠せる）、右に選んだクエストの詳細。詳細に手紙と、道のり／日付／インプットのタブがある。「＋ 新規」でクエストを出す |
| 新しいクエスト | 依頼の内容・日付・インプットに加えて、納品物の形式（Markdown・HTML・プロンプト）を選べます。PowerPoint・Excel・Word・PDF・画像は、形式で「プロンプト」を選び、作るファイルを選ぶと、Claude Code に貼るプロンプトが納品物になります。タイトルは受付係が自動で付けます（分解前は依頼文の先頭 24 字）。同じ種類の依頼は「関連（series）」で結びつき、一覧で絞れます。タイトルと関連は、詳細の「題名・関連を直す」で直せます |
| 納品物 | 納品物・成果物・報告・書庫・インプットを、左のメニューで種類を選び（初めは納品物）、依頼別・種類別・検索で探せます。名前を押すと、Markdown（見出し・表・リスト。```mermaid の図も）・HTML（スクリプトを止めた枠）を整形して開きます（Mermaid の描画部品は、見るときにインターネットから読み込みます。読めないときは、図のソースを表示します）。「文章をコピー」「パスをコピー」でチャットに貼れます。インプットには、使った依頼が出ます |
| クエストログ | 依頼ごとの進み・あなたの番・担当の職業・止まっている理由・次の提案を、事実だけでまとめた記録（待機の直前と完了時に、機械が作ります）。失敗の手紙には、鑑定士の「おすすめ」（もう一度／計画を直す／やめる）が出ます |
| クエスト進捗 | 選んだクエストの開始日〜締切のガントチャートと、目標の予定日、あなたの実行の日ごとの件数 |
| 納品物 | 受け取った納品物とプロンプトの一覧とコピー |
| 書庫 | 閲覧・検索・登録・編集。項目にインプットを紐づけられる |
| 外部サイト | 開けるサイトの許可リスト |
| Obsidian | Obsidian で読む手順 |
| ヘルプ | 処理フローの図、役の説明、使い方、困ったとき |

## ギルドの顔ぶれ（役）

| 役 | 名前 | やること |
|---|---|---|
| ギルドマスター | `/guild:quest` 本体 | 依頼の受け付け、`guild.py` の実行、役の呼び出し、ボードの答えの待機 |
| 受付係 | `receptionist` | 依頼を目標に分解し、タイトル・関連（`series`）・種別・職業（`class`）・影響（`effects`）・納品物の構成と置き場・合格基準・使うインプットを決める。全目標の合格後に、総合確認もする |
| 魔法使い | `wizard` | 外部の情報を調べる・比べる・出典を確かめる（許可されたサイトだけ開ける） |
| 錬金術師 | `alchemist` | すでにある材料から、文章や表を書く・整理する（Web には出ない） |
| 冒険者 | `adventurer` | ブラウザで動的ページを読む（読むだけ）。出典の確認もする |
| 鑑定士 | `appraiser` | 成果物を合格基準で判定する（成果物は直さない）。不合格には「勧める対応」を添える |
| 司書 | `librarian` | 書庫に残す候補・次の提案・掟の提案・職業ごとの経験の要約を挙げる（登録は `guild.py` が検査して行う） |

`auto` の目標には、受付係が職業（`class`：`wizard`・`alchemist`・`adventurer`）を決め、その役が実行します。全役は、作業の最初に**ギルドの掟**（共通ルール。`guild/.work/codex/default.md`。このプロジェクトだけの追記は `project.md`）を読みます。

モデルなど役の詳細は [docs/roles-spec.md](docs/roles-spec.md) です。

## ファイルはどこにできるか

```
guild/
  board.html      ボード
  archive/        書庫
  deliverables/   納品物とプロンプト（Q001_….md / .prompt.md）
  inputs/         共通のインプット
  .work/          作業用（Obsidian には出ない）
    config.json   設定（Python のパスなど）
    codex/        ギルドの掟（default.md は init が更新。project.md は追記用）
    Q001/ など    依頼ごとのフォルダ
```

あなたが読む・置く場所は、`inputs/`・`deliverables/`・`archive/`・`board.html` の 4 つだけです。ほかは `.work/` の下にあります。

## つまずいたとき

- **`/guild:init` が「Playwright MCP が見つかりません」で止まる**: `playwright` という名前で MCP を導入・接続してから、もう一度実行します。`guild/` はこの時点では作られません。
- **Python が見つからない**: Windows では、`python` がストアへの誘導だけで動かないことがあります。`py` か `python3` で動く Python 3 を入れてください。
- **`/guild:quest` が「/guild:init を先に」と止まる**: そのフォルダで `/guild:init` を実行します。
- **ボードで答えたのに進まない**: ボードの答えを受け取って進めるのは、動いている `/guild:quest` です。止まっていたら、もう一度 `/guild:quest` を実行すると、続きから進みます。
- **ボードが「フォルダを選ぶ」から先に進まない**: Chrome か Edge で開き、`guild/` の 1 つ上のフォルダを選びます。
- **納品物が `guild/deliverables/` にない**: `/guild:quest` に、納品物を置き直すよう伝えます（`guild.py publish`）。

## 開発する人へ

計画や消化の質が上がったかは、`guild.py stats <プロジェクトのフォルダ>` で見られます（依頼ごとの不合格・もう一度やる・計画の直しの回数）。

構成:

- `skills/` — `init`、`quest`（`guild.py`、`webaccess.py`、`board.html`、`transitions.json`、`codex.md`（既定のギルドの掟））
- `agents/` — 各役の指示書
- `hooks/` — 魔法使いの WebFetch を許可リストで判定するフック
- `docs/` — 設計の文書
- `tests/` — テスト

テストは次で実行します。

```
python -m unittest discover -s tests
```
