# SPEC：書庫（archive）— guild の知識の蓄積・管理・活用

## 概要
- **目的**：現在の `knowledge/<依頼番号>.md`（依頼ごとの成功／失敗／業務知識の混在ログ）は、システム改善の記録以外は次の依頼で役に立たない。これを、**技術用語・社内用語・業務フロー・業務情報を種類別に蓄積・管理し、全役が使える**形に作り替える。
- **ゴール（完了の判定）**：(1) 教訓（システム改善）が残る (2) 用語・フロー・事実が 1 項目ずつ蓄積される (3) 全役が読み、使った跡が報告に残る。
- **名称**：ボードのタブ名は「書庫」、フォルダは `guild/archive/`。「ノウハウ」「knowledge」の呼び名は廃止する。

## 構成
```
guild/archive/
  index.md        索引（項目の名前・別名・種類・確度・状態・1 行説明）
  <名前>.md       項目（フラット。サブフォルダなし）
```
種類は項目の `type` で持つ：`term` 用語（技術用語・社内用語）／`flow` 業務フロー・手順／`fact` 業務情報（料金・上限・設備・取り決めなど）／`personal` 個人（依頼主個人の情報。役職・文体の好み・禁止事項など。依頼主が明言したものだけ）／`lesson` 心得（システム改善の教訓。役は読まない）。

1 項目 1 ファイル。先頭の見出し情報：`name` / `type` / `aliases` / `inputs`（関係する `guild/inputs/` のファイル名のリスト。任意）/ `confidence` / `source` / `confirmed`（確認日）/ `status`（有効・廃止）。

## 確度（3 段階）
| 値 | 意味 | 読む役の扱い |
|---|---|---|
| 確認済み | 依頼主が確認した | 事実として使う |
| 出典あり | 公開情報で出典（URL・閲覧日）がある | 出典つきで使う |
| 推測 | 確かめていない | 参考。断定に使わない |

## 流れ
1. **溜める（依頼完了／中止時）**：新しい役 **司書**（仮称。下の決定ログ）が、各 Todo の報告・鑑定の指摘・成果物から「用語／フロー／事実／個人／心得」の候補を抽出し、`reports/` に候補ファイルを書く。登録前に索引で同名・別名を検索し、あれば「更新」の候補にする。
2. **確認**：ギルドマスターは、候補を **依頼ごとに 1 通の手紙**にしてボードに出す（項目ごとに「登録／不要」）。用語・フロー・事実・個人は、依頼主が登録を選んだものだけ `archive/` へ入る。心得（`type: lesson`）は確認なしで登録する（役が読まないため、推測が業務に影響しない）。
3. **手で入れる**：ボードに、用語・フロー・事実を依頼とは無関係に登録・編集する入力欄を置く。入力は `inbox/` の JSON として届き、`guild.py` が取り込む（既存の答えの経路と同じ）。
4. **使う**：全役（地図師・冒険者・斥候・鑑定士）が、作業の前に `archive/index.md` を見て、関係する項目だけ読む（`type: lesson` の項目は除く）。**使った項目を報告の「使った書庫の項目」欄に書く**（なければ「なし」）。
5. **管理**：(a) 登録前に同名・別名を検索し重複を防ぐ (b) 確認日から 1 年を過ぎた項目は、読む役が「古い可能性」と添える (c) 矛盾する値は上書きせず、両方を出典つきで残して「要確認」にする (d) 廃止は削除せず状態を「廃止」にし、理由と日付を残して索引から外す。

## 種類の付け替え
登録済みの項目の種類は、ボードの「種類を変更」で付け替えられる（`.work/archive-inbox/` の `retype`）。項目の `type` を書き換え、索引が更新される（ファイルは移らない）。確度・確認日・出典・本文は引き継ぐ。移動先に同名・同じ別名の項目があるときと、廃止済みの項目は拒否する。心得への付け替え、心得からの付け替えはできない。

## インプットへの紐づけ
項目の `inputs` に、その項目に関係する `guild/inputs/` のファイル名を並べられる（`aliases` と同じリストの見出し情報）。依頼主はボードの書庫の登録・編集欄で付け、司書は候補（`archive-draft.json`）に任意で書く（依頼主の確認を通って登録される。更新の候補では、既存の `inputs` に足される）。名前の形だけを検査し、存在は検査しない（ファイルの上書き・削除で外れても、項目は壊れない）。索引にも載る。

`guild.py inputs-list <root> --text <依頼文>` は、依頼文に名前・別名が出てくる項目（確認済みか出典ありで、使われているもの。3文字以上の語だけ。心得は除く）の `inputs` のファイルに、ヒント「書庫の用語『KGI』→ このファイル」を付けて先頭に並べる。地図師は、これを手がかりにインプットを選ぶ。

## ボード（タブ名「書庫」）
- 全種類を縦に並べ、左の目次で見出しへ飛ぶ。検索（確度・状態つき）。廃止した項目も印つきで並ぶ
- 用語・フロー・事実の登録・編集欄
- 依頼完了時の「登録候補の確認」の手紙
- 確度の昇格操作（推測／出典あり → 確認済み）
- 心得は別枠で閲覧（役は読まない）

## 受入条件
1. `guild.py init` が `archive/`（`index.md`）を作る。何度実行しても既存の項目は消えない。
2. 依頼の完了／中止後に、候補の手紙がボードに 1 通出て、項目ごとの「登録／不要」で `archive/` に反映され、`index.md` が更新される。
3. ボードの入力欄から登録した項目が、`archive/` に作られ、索引に載る。
4. 全役の指示書に「索引を見る・使った項目を報告に書く」が入り、テスト実行の報告に「使った書庫の項目」欄が現れる。
5. 同名・別名の項目の登録は、新規でなく「更新」の候補になる。矛盾は両論併記になる。
6. 現行の `knowledge/` への参照（`SKILL.md`・各 agents・`board.html`・`guild.py`・docs・tests）がすべて新しい構成に置き換わり、`tests/test_guild.py` が通る。
7. 実際の依頼を 1 件流し、2 件目の依頼で、1 件目の項目が使われたことが報告に残る（今回の点検でできなかった確認）。

## 非目標
- 依頼ごとの経緯ログ（成功／失敗の物語）を持たない。
- DB・外部サービス・全文検索エンジンは使わない（Markdown と Grep）。
- 鑑定士にウェブを開く手段がない問題そのものの解決（心得に記録するだけ。別件）。
- 心得を guild 本体に自動で反映する仕組み。
- 項目の使用状況をボードで可視化する機能（後回し）。
- 機密情報（トークン、キー）を項目に書く運用（書かない決まりを指示書に入れるのみ）。

## リスク
- 依頼主が確認の手紙に答えないと、書庫が溜まらない（確認が重いと放置される）。→ 1 依頼 1 通・項目ごとに選ぶだけ。
- 司書の抽出の質が低いと、不要な候補で手紙が重くなる。→ 候補数の上限と「登録基準」（再利用できる／出典がある）を指示書に書く。
- 全役が索引を読むため、読み込みが増える。→ 索引は 1 行説明にとどめ、項目は関係するものだけ読む。
- 役が索引を見ない・使っても報告に書かない。→ 報告の欄を鑑定の確認項目に入れる。
- 社内用語・フローは公開調査から出ないため、手で入れる入口が使われないと価値が出ない。
- 役が 1 つ増え、指示書・ドキュメント・テストが増える。

## 決定ログ
| 項目 | 決定 | 根拠 |
|---|---|---|
| 種類 | 心得・用語・フロー・事実 | 依頼主の方針。経緯ログは廃止 |
| 入手 | 自動抽出＋依頼主確認＋手動登録 | Q5 |
| 確度 | 3 段階 | Q6 |
| 構成 | `archive/` の下に種類別＋索引 | Q7、knowledge に限らない（Q3 補足） |
| 読む役 | 全役が索引から。心得は除く。使った項目を報告に書く | Q8、Q10 |
| 項目の形 | 1 項目 1 ファイル＋見出し情報 | Q9 |
| 心得の置き場 | プロジェクトの `archive/` に `type: lesson` の項目として置く。ボードの別枠で見て、本体へは手で反映 | Q10 |
| 抽出と確認 | 専用の役が抽出、確認は 1 通の手紙 | Q11 |
| 管理 | 重複検索・確認日・両論併記・廃止は状態で | Q12 |
| ボード | 一覧と検索／入力欄／確認の手紙／昇格 | Q13 |
| 名称 | 書庫（`archive/`） | Q14 |
| 個人 | 第5の種類として追加（`type: personal`）。全役が索引から読む。司書の候補は確認の手紙を通し、自動登録しない | 2026-10-11 ボード改善 |
| 種類の付け替え | 同名は拒否・確度などは引き継ぐ・心得は対象外・履歴は残さない | 2026-10-11 ボード改善 |
| 既存 knowledge | 破棄。ただし『鑑定士はウェブを開けず出典照合が未検証』は心得として最初に登録してから | Q15 とご指摘。**破棄の実行前に中身を確認し、実行前に確認を取る** |
| 役の名前 | **司書**（提案。「記録係ではない名前」の希望に対し、書庫との対応で選んだ）。ほかの候補：書記、語り部、賢者 | 未決。承認時に変更可 |
| 心得は確認なしで登録 | 提案（役が読まないため） | 未決。承認時に変更可 |
