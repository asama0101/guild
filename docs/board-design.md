# ボード（`guild/board.html`）の設計メモ

依頼主が使う画面。`/guild:init` が `guild/board.html` に置く。正本は `skills/quest/board.html`（1ファイル、外部通信なし）。

## 決めたこと（デザインの検討の結果）

- **1ページで完結**：画面を移らない。上のタブは「掲示板／納品物／書庫／冒険の書／ギルド案内／Obsidian／ヘルプ」の7つ。納品物＝受け取った納品物の一覧とテンプレート、書庫＝`archive/`（用語・業務フロー・業務情報・個人・心得）の閲覧・検索・種類別のサブタブ・確度と状態の絞り込み・並び替え・登録・編集・種類の付け替え・確認済みへの昇格・廃止。Obsidian＝`guild/` を Vault にして書庫と納品物を読む手順の案内（読むだけ）。依頼完了後の登録候補の確認は、「掲示板」の手紙、ギルド案内＝処理フローの図と、スキル・役の説明。
- 受付待ちの依頼は取り消せる（ファイルを消す）。進行中の依頼は、「この依頼を中止する」（確認あり）。中止した依頼の手紙には、合格（`done`）した Todo の成果物だけを「中止（一部の成果物あり）」として並べる（納品物ではなく途中までのもの。未鑑定・不合格のものは載せない。なければ載せない）。
- 全 Todo が済むと、「受け取りの確認」の手紙が出る（納品物を開いてコピーできる。「受け取る」か、コメントを添えた「直してほしい」）。依頼主が受け取るまで完了にならない。
- **掲示板**：上に「あなたの番」の帯と、新しい依頼の入力欄（書いて「依頼」の1回で保存）。その下に状態のフィルタと、依頼の一覧（台帳）。選んだ依頼の行が開き、中に「手紙」（いま必要な用件）と「道のり」（Todo の札）が出る。左に、依頼の目次（固定）があり、押すと、その依頼の位置へ移動して開き、数秒の強調とキーボードフォーカスを付ける（画面幅が900px以下では、目次は出さない）。
- **Todo の期限**：「道のり」の各 Todo に、任意の期限（日付のみ）を付けられる。承認前でも進行中でも、画面から設定・変更・解除できる（`Q###/inbox/` に `type: due`。`guild.py` が `plan.json` に反映するまで「反映待ち」と出す）。その日の終わり（23:59）を過ぎた未完了の Todo に「期限切れ」の印。表示と警告だけで、実行順や「あなたの番」は変えない。依頼の期限より後の日付には注意を出す。
- **ヘルプのモデル表**：各役のモデルを載せる。正本は `agents/*.md` の `model` で、画面の `ROLE_MODELS` との一致をテストで確かめる。
- **状態のフィルタ**：掲示板と冒険の書の両方で、状態（承認待ち・進行中・要判断・受け取り待ち・完了・中止）を複数チェックで絞る。何も選ばなければ、すべて出る。目次も同じ絞り込みに従う。
- **件数の区切り**：依頼の一覧は、新しい順に20件まで出し、残りは「さらに古い依頼を表示」で20件ずつ足す（掲示板・冒険の書それぞれ）。目次や「あなたの番」から、区切りの外の依頼へ移動するときは、その依頼まで自動で広げる。画面は3秒ごとに全依頼を読み直すので、依頼が非常に多くなったときの性能は、まだ測っていない。
- **手紙**：質問（計画ができる前の聞き取り）、計画の承認、あなたの実行（結果の入力）、実行前の確認、失敗の判断、完了。答えは `inbox/` に JSON で書く。
- **冒険の書**：依頼をプルダウンで選び（または「すべての依頼」）、役たちとのやりとりを新しい順に見る。役ごとに絞り込め、各発言から報告書を開ける。やりとりは新しい順に50件まで出し、「さらに古いやりとりを表示」で50件ずつ足す（依頼・役・状態の絞り込みを変えると、50件に戻る）。タイムライン（実績の帯）は、掲示板の依頼の「道のり」の下に出る。
- **ヘルプ**：使い方、印の見方（依頼の状態と Todo の状態）、言葉の説明、困ったとき。スキル（コマンド）の説明は、ギルド案内にだけ置く。
- **ギルド案内**：処理フローの図（鑑定士が開けない出典を斥候が読む分岐を含む）、スキル、役、`guild/` の中身。
- **書庫**：項目が0件の種類は、見出しを出さず1行にまとめる。用語などの折りたたみ行に、概要の冒頭を出す。
- **カードの並び**（ギルド案内・ヘルプ）：高さをそろえず、2段に詰める。
- **見た目**：ギルド調。看板は深紅に金の文字、紙の上に封蝋と朱肉の印。配色は案G1・背景1（羊皮紙）。色は `:root` の変数で持つ。

## 読み書きの契約

- 画面が書けるのは `guild/` の中の次の場所だけ。`plan.json` は書かない（書くのは `guild.py` だけ）。
  - `requests/R<日時>.json`（新しい依頼。素材は `requests/files/R<日時>/`）
  - `Q###/inbox/<日時>-<種類>[-<Todo>].json`（質問への回答・承認・直す・中止・確認・結果・判断。添付は `inbox/files/`）
- 依頼主への質問・承認・確認・結果・判断は、すべてこの画面の「手紙」で行い、チャットでは聞かない。`/guild:quest` は `guild.py wait` で入力の到着を待ち、届いたら `guild.py ingest`（計画前の質問への回答は `guild.py answers`）で取り込んで進める。動いていないときは、チャットで `/guild:quest` と送ると読み取る。
- 画面は3秒ごとに `guild/` を読み直す。読むのは `Q###/plan.json`（状態と `history`）、`reports/`、`output/`、`inbox/`、`requests/`、`archive/`、`Q###/archive.json`（登録候補の確認待ち）。
- タイムラインと会話は、`plan.json` の `history`（`guild.py` が状態を変えるたびに時刻つきで追記する）から作る。

## 動作環境と制約

- **Chrome または Edge**：フォルダへの書き込み（File System Access API）を使う。Firefox・Safari では保存できない。
- **許可はブラウザを開き直すたびに求められる**ことがある。画面の「再接続する」で許可する。
- **保存に失敗したとき**は、理由を画面に出し、送る内容を「コピー」できる形で見せる（チャットに貼る）。
- フォルダを覚える入れ物（IndexedDB）が壊れていても、作り直して続ける。覚えられなかったときは、理由を出す。
- **見本**：`board.html?demo=human`（ほかに `plan`・`confirm`・`failed`・`done`）で、保存せずに見られる。
