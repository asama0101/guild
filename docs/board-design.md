# ボード（`guild/board.html`）の設計メモ

依頼主が使う画面。`/guild:init` が `guild/board.html` に置く。正本は `skills/quest/board.html`（1ファイル、外部通信なし）。

## 決めたこと（デザインの検討の結果）

- **1ページで完結**：画面を移らない。上のタブは「クエスト掲示板／クエスト進捗／納品物／書庫／外部サイト／Obsidian／ヘルプ」の7つ。タブの右に「＋ 新規」がある。
  - クエスト掲示板＝左にクエストの一覧、右に選んだクエストの詳細（手紙と、道のり／日付／インプットのタブ）。
  - ファイル＝納品物・成果物・報告・書庫・インプットの一覧（依頼別／種類別／検索）。開くと、Markdown・HTML（`sandbox` の iframe。スクリプトなし）・Mermaid（CDN から描画。読めなければソース）を整形して表示。「ソースで見る」で文字のまま。
  - クエストログ＝`guild.py digest` が作る記録（`.work/clog.json`）。あなたの番・進行中（担当の職業）・止まっている理由・次の提案・集計。LLM は使わない。
  - クエスト進捗＝選んだクエストの開始日〜締切のガントと、目標の予定日・human の日ごとの件数。
  - 納品物＝受け取った納品物とプロンプト（`*.prompt.md`）の一覧・コピー。
  - 書庫＝`archive/`（用語・業務フロー・業務情報・個人・心得）の閲覧・検索・登録・編集・種類の付け替え・確認済みへの昇格・廃止。
  - 外部サイト＝魔法使いの WebFetch を許可するドメインのリスト（追加・削除。許可の確認の手紙はクエスト掲示板に出て、許可待ちがあるとタブに件数が付く）。
  - Obsidian＝`guild/` を Vault にして書庫と納品物を読む手順の案内（読むだけ）。
  - ヘルプ＝処理フローの図と役の説明、使い方・印・言葉・困ったとき。
- **クエスト掲示板（一覧）**：左の一覧は、番号・題名で探す欄と、区分のチップ（すべて・あなたの番・進行中・受け取り待ち・完了。件数つき）で絞る。「すべて」では完了・中止を畳み、「完了・中止 n件を表示」で出す。受付待ちの依頼（`.work/requests/`）は先頭に「受付待ち」で並び、取り消せる（ファイルを消す。確認あり）。上に「あなたの番」の帯（押すとそのクエストを開く）と、受け付けられなかった依頼の知らせ（`.work/requests/rejected/` の理由。新しい5件まで。「出し直す」で「＋ 新規」に依頼文が入る）。
- **一覧を隠す**：一覧は既定で表示。詳細の上の「一覧を隠す」で隠すと、詳細が広がり、ツールバーに見出し・「‹ ›」（一覧に見えている順で前後のクエスト）・「N件中M件目」・クエストを探して開く欄・「＋ 新規」が出る。「一覧を表示」で戻る。隠したかどうかは `localStorage` の `guild.board.listOpen`（`true`／`false`）に覚え、開き直しても保つ。
- **狭い画面**（幅 760px 以下）：一覧と詳細を並べず、切り替える（クエストを選ぶと詳細、「‹ 一覧へ戻る」で一覧）。横スクロールを出さない。
- **詳細**：見出し（番号・状態・題名・開始日と締切・済んだ割合）、「進捗で見る」（そのクエストだけを選んだクエスト進捗を開く）、いま必要な手紙、詳細のタブ（道のり／日付／インプット。矢印キーで移れる）、「この依頼を中止する」（確認あり）。
  - **道のり**：目標の行（番号・種別・題名・予定日・締切・状態。日付の矛盾の注意）。行を開くと、合格基準、`human` の指示、報告（魔法使い・錬金術師・冒険者・冒険者の出典の確認・あなた・鑑定士の `reports/<id>-<役>.md` の冒頭の抜粋と、開くボタン）が出る。広い画面では、開いた目標の合格基準を右に並べる。
  - **日付**：このクエストのミニガント（帯は依頼の開始日〜締切、◆ は目標の予定日で色は状態、赤い点線は今日）と、依頼の開始日・締切、目標ごとの予定日・締切の表。直した欄は色が変わり、矛盾（締切が開始日より前、予定日が依頼の開始日より前・前提の目標より前など）は、行の「注意」の欄に文で出す（`--warn` の色）。注意は表示だけで送れる。ほかの目標の日付は連動してずらさない。「変更を送る（n件）」で、変えたものだけを `type: due` の入力として送る（依頼の日付は1件、目標ごとに1件）。「元に戻す」で下書きを捨てる。空の欄は今の値のまま（目標の締切だけは、空にすると解除）。中止・見直し中・受け取り後は直せない。
  - **インプット**：このクエストのインプット（`plan.json` の `inputs`）を「指定」（依頼主）・「自動」（受付係）の印と理由、更新日つきで並べ、`guild/inputs/` にないものはその旨を出す。受付係が迷った候補（`candidates`）は「候補」の印で並び、「追加」で入れられる。「外す」「既存から選ぶ」（検索つきのチェックリスト）で直すと、`type: inputs` の入力を送る（`guild.py` が反映するまで「反映待ち」）。文字のファイル（`.md` `.txt` `.csv`）は画面で開け、ほかは「パスをコピー」。出したあとでも、タブの下の欄からアップロードでき、`guild/inputs/` に置いてそのクエストのインプットに足す（`type: inputs` の入力）。同名のファイルがあるときは、バックアップが残らないので置かずに知らせる（上書きは「＋ 新規」から）。
- **ギルドを閉める**：タブの右の「ギルドを閉める」ボタン。確認のあと `guild/.work/pause.json` を書く（`guild.py pause` と同じ。論理パスは `pause.json`）。あるあいだは、上に「ギルドを閉める準備中です」の帯（「取り消す」で pause.json を消す）。ギルドマスターは、新しい役を呼ばず、実行中の役が終わったら止まる。依頼は中止にならない。再開は `/guild:quest`（起動時に `pause-clear` で消す）。チャットからは `/guild:close`。
- **「＋ 新規」ダイアログ**：依頼の内容、開始日（未指定なら今日）、締切（未定なら開始日）、インプット（既存から選ぶ・アップロード）を書いて「クエストを出す」。アップロードに `guild/inputs/` と同じ名前があると「同名あり（上書き）」と出す（古い版は、そのクエストが閉じるまで `.work/backup/` に残る）。Esc・「閉じる」・外側のクリックで閉じ、開いている間は Tab がダイアログの中を回る。
- **稼働の印とタブの件数**：`guild/.work/heartbeat.json`（`guild.py wait`・`arrivals` が書く）を読み、パネルの上に「/guild:quest：待機中（60 秒以内）／作業中（60 分以内。印が未来の時刻のものは使わない）／停止中」を出す（3 秒の更新ごとに、印の時刻から計算し直す。この印は変更判定の対象外で、10 秒ごとの書き換えで画面を作り直さない）。「あなたの番」が増えたら、タブの題に件数を出す（デスクトップ通知は出さない）。
- **流れの注意**：道のりの目標に、止まっている原因（失敗した前提を根本まで辿る）、やめた前提（結果がないまま進む）、前提の完了待ちを出す。承認前は出さない。
- **手紙**：質問（計画ができる前の聞き取り）、計画の承認（選ばれたインプットつき。受付係の自己点検の `brief`、計画の警告 `check.warnings`、あなたの作業量 `workload`、再計画の差分 `replan_diff` も出す）、あなたの実行（結果の入力）、実行前の確認、失敗の判断（鑑定士の指摘の抜粋つき。この目標だけやめる／後続もやめる／計画を直す／中止）、受け取りの確認（納品物とプロンプトを分けて並べ、開く・コピーできる。「受け取る」か、コメントを添えた「直してほしい」）、完了、中止、書庫の登録候補の確認、外部サイトを開く許可。答えは `inbox/` などに JSON で書く。
  - 全目標が済むと「受け取りの確認」の手紙が出る。依頼主が受け取るまで完了にならない。
  - 中止した依頼の手紙には、合格（`done`）した目標の成果物だけを「中止（一部の成果物あり）」として並べる（納品物ではなく途中までのもの。未鑑定・不合格のものは載せない。なければ載せない）。
- **期限切れ**：その日の終わり（23:59）を過ぎた未完了の目標の締切を赤く出す。表示と警告だけで、実行順や「あなたの番」は変えない。
- **クエスト進捗**：ガントに出すクエストを選べる。「表示するクエスト」のボタンで開く一覧（番号・題名で探す欄。あなたの番・進行中・受け取り待ち・完了・中止の群。「表示中の全部を選ぶ」「選択を解除」）と、すぐ選ぶボタン（進行中だけ・自分の番だけ・期限が近い5件）、選んだクエストのタグ（× で外す）、「完了・中止した依頼も含める」。選んでいないクエストは、ガントにも human の件数にも出ない。選択は `localStorage` の `guild.progress.sel`（クエストの番号の配列。`null` か無いときは、進行中のすべて）に覚える。消えたクエストの番号は落とす。
- **ブラウザの保存（`localStorage`）**：使うのは `guild.board.listOpen` と `guild.progress.sel` だけで、読み書きは `lsGet`・`lsSet` を通す。使えない環境（プライベートウィンドウ、保存の拒否など）では、毎回の既定（一覧を表示、進行中のすべて）で動く。
- **書庫で反映されなかった入力**：`.work/archive-inbox/rejected/` に `guild.py` が残す理由（`<入力>.reason.txt`）を、書庫タブの上に新しい5件まで出す（種類の付け替えが同名で断られたときなど）。
- **書庫の探し方**：納品物タブと同じ形。左のメニューで種類（用語・業務フロー・業務情報・個人・心得・すべて。初めはすべて）を、件数つきで選ぶ。言葉で探す欄は、本文・別名・インプットも探す。廃止した項目も、「廃止」の印つきで並ぶ。登録欄（「自分で項目を登録する」）はいつも開いている。項目が0件の種類は、見出しを出さず1行にまとめる。折りたたみ行に、概要の冒頭を出す。
- **書庫のインプット**：登録・編集欄の「別名・出典・インプットをつける」に、`guild/inputs/` のファイル名を1行に1つ書ける（入力の `entry` の `inputs`）。ファイルがなくても保存でき、項目には「（guild/inputs/ にありません）」と出す。
- **各役のモデル**：ヘルプの役の一覧にだけ載せる。正本は `agents/*.md` の `model` で、画面の `ROLE_MODELS` との一致をテストで確かめる。
- **ヘルプ**：上に、処理フローの図（鑑定士が開けない出典を冒険者が読む分岐、「まとめの目標」が実行ループの最後であること、「実行しない」「できなかった」も失敗の判断へ行くこと、中止、書庫への記録が完了・中止の両方で行われることを含む）、役（モデル・呼ばれるとき・やること）。その下に、使い方、クエスト掲示板の使い方、スキル（`/guild:init`・`/guild:quest`）の使い方、印の見方、言葉の説明、困ったとき。
- **カードの並び**（ヘルプ）：高さをそろえず、2段に詰める。
- **見た目**：ギルド調。看板は深紅に金の文字、紙の上に封蝋と朱肉の印。配色は案G1・背景1（羊皮紙）。色は `:root` の変数で持つ。

## 読み書きの契約

- 画面が書けるのは `guild/` の中の次の場所だけ。`plan.json` は書かない（書くのは `guild.py` だけ）。
  - `.work/requests/R<日時>.json`（新しい依頼。`text`・`start`・`due`・`inputs`（既存から選んだ名前）・`files`（アップロードの名前）。アップロードの中身は `.work/requests/files/R<日時>/`。取り込むと共通の `inputs/` に置かれる）。受付待ちの取り消しでは、このファイルと素材を消す。
  - `.work/Q###/inbox/<日時>-<種類>[-<目標>].json`（質問への回答・承認・受け取り・直す・中止・確認・結果・判断・日付・インプット・書庫の登録候補への答え。添付は `inbox/files/`）
  - `.work/archive-inbox/*.json`（書庫への直接の登録・編集・昇格・廃止・種類の付け替え）
  - `.work/web/inbox/*.json`（外部サイトの許可の答え、許可リストの追加・削除）
- 入力の種類と形は `docs/graph-format.md` が正本。
- 依頼主への質問・承認・確認・結果・判断は、すべてこの画面の「手紙」で行い、チャットでは聞かない。`/guild:quest` は `guild.py wait` で入力の到着を待ち、届いたら `guild.py ingest`（計画前の質問への回答は `guild.py answers`）で取り込んで進める。動いていないときは、チャットで `/guild:quest` と送ると読み取る。
- 画面は3秒ごとに `guild/` を読み直す。読むのは `.work/Q###/`（`plan.json`、`request.json`、`reports/`、`output/`、`inbox/`、`archive.json`）、`.work/requests/`（と `rejected/`）、`.work/archive-inbox/`、`.work/web/`、`archive/`、`deliverables/`、`inputs/`。
- 画面の中の名前（`requests/`、`Q###/`、`web/`、`archive/inbox/`）は、読み書きのときに実フォルダ（`.work/requests/`、`.work/Q###/`、`.work/web/`、`.work/archive-inbox/`）に置き換える（`PHYS`）。

## 動作環境と制約

- **Chrome または Edge**：フォルダへの書き込み（File System Access API）を使う。Firefox・Safari では保存できない。先頭が `.` のフォルダ（`.work/`）も読み書きする。
- **許可はブラウザを開き直すたびに求められる**ことがある。画面の「再接続する」で許可する。
- **保存に失敗したとき**は、理由を画面に出し、送る内容を「コピー」できる形で見せる（チャットに貼る）。
- フォルダを覚える入れ物（IndexedDB）が壊れていても、作り直して続ける。覚えられなかったときは、理由を出す。
- **見本**：`board.html?demo=human`（ほかに `plan`・`questions`・`confirm`・`failed`・`accept`・`done`・`archive`）で、保存せずに見られる。
- 画面は3秒ごとに全依頼を読み直すので、依頼が非常に多くなったときの性能は、まだ測っていない。
