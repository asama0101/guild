# guild の役 SPEC（`docs/spec.md` の追補）

## 概要

- **目的**: 最初の版の役（サブエージェント）の構成、責任、道具、モデルを決め、`agents/*.md` と `skills/quest/SKILL.md` を書き始められるようにする。
- **前提**: 進め方の判断（順序・遷移・リトライ）は `guild.py` と `transitions.json` が持つ。役は『作業と報告』だけで、判断しない。
- **公式ガイドの反映**: 『1役1作業』『description は他と区別できるほど具体的に』『ツールは必要な分だけ』。非フォークのサブエージェントは会話履歴を見ないので、呼び出しのメッセージに入力のパス・合格基準・出力先を毎回書く。
- **名前の変更（2026-10-17 の再編）**: 地図師→受付係、冒険者（調べる・書く兼任）→魔法使い・錬金術師に分割、斥候→冒険者。下の決定ログの Q4〜Q15 などは、決めた時点の旧名称（地図師・冒険者・斥候）のまま残している。「冒険者」の語は、再編後は旧斥候だけを指す。

- 目標の `class` の決め方（受付係の指針）：外部の情報を調べる・比べる・出典を確かめる → `wizard`。材料から書く・整理する（まとめの納品物を含む） → `alchemist`。動的ページを読む → `adventurer`。動的ページを魔法使いが読めなかったときの再計画では、`adventurer` の目標にする。ログイン必須などで読めないものは、従来どおり `human`。旧 `needs_browser: true` は、`class: adventurer` に置き換えた。
- **ギルドの掟**（共通ルール）は、既定を `skills/quest/codex.md` に 1 か所でまとめ、`/guild:init` が `guild/.work/codex/default.md` にコピーする（毎回更新）。プロジェクトの追記は `guild/.work/codex/project.md`。全役（受付係・魔法使い・錬金術師・冒険者・鑑定士・司書）が、作業の最初に両方を読む。役ごとの固有の手順は `agents/*.md` に残す（鑑定士の独立性の手順など）。
- 受付（聞き取り）は、専任の役を置かず、受付係が分解と兼ねる。受付係が『聞くべきこと』（`questions`）を `plan-draft.json` に書き、ボードが「質問」の手紙にして依頼主に出す。ギルドマスターは質問せず、回答を `guild.py answers` で取り出して受付係に渡す（Q7。のちに、質問はすべてボードで行うと決めた）。
- 記録（旧ノウハウ）は、書庫（`archive/`）に置き換え、専任の司書を置いた（`docs/archive-spec.md`）。全役が作業の前に `archive/index.md` を見て、使った項目を報告の「使った書庫の項目」に書く。心得（`type: lesson` の項目）は役が読まない。
- 旧版の『受付嬢』は引き継がない。受付の役は、性別を含まない『受付係』にした（2026-10-17 の再編で、地図師を受付係に改めた）。

## モデルの方針と割り当て（Q12-D）

- 方針：探索・検索のような単純な作業は `haiku`、ほとんどの作業は `sonnet`、複雑な設計判断だけ `opus`。
- 割り当て（提案）：
  - 受付係：分解は依頼ごとに1回で、後工程すべてに響く設計判断なので `opus`。
  - 魔法使い・錬金術師・冒険者：調査も文書作成もブラウザ読みも『ほとんどの作業』なので `sonnet`。
  - 鑑定士：目標ごとに繰り返す判定で、『薄くならない』の要。公式に判定役の推奨はないが、判断の質を優先して `sonnet`。
- エイリアス（`opus` `sonnet` `haiku`）は提供元の推奨版に更新される。特定の版に固定したくなったらモデルIDを書く。
- 見直しのきっかけ：費用が過大、または特定の役の質が落ちたとき。

## 冒険者を分ける条件（Q5-C。2026-10-17 に実施済み）

最初は1役（冒険者）だった。次のいずれかを満たしたら、『調べる役（Web を読む）』と『書く錬金術師（Web なし）』に分ける、と決めていた。

1. 書く目標の大半が、外部サイトを読まずに済むと分かった（Web を読む権限を調べる役に閉じ込められる）。
2. 合格基準で『出典がない』と『文章が浅い』が、別々に繰り返し不合格になった。

2026-10-17 の再編で分けた。調べる役は『魔法使い』（`wizard`）、書く・整理する役は『錬金術師』（`alchemist`。Web なし）とし、旧斥候を『冒険者』に改めた。理由は決定ログの「2026-10-17 の再編」に書いた。

## 受け渡し（Q8-A）

- 各役は `guild/.work/<依頼>/reports/<目標 ID>-<役>.md` に、固定の見出しで報告を書く（`<役>` は `wizard`・`alchemist`・`adventurer`・`appraiser`・`user`。出典の確認は `<目標 ID>-verify-adventurer.md`）。返り値は『書いた場所』と一言の結果だけ。書式は、ギルドの掟（`skills/quest/codex.md`）にまとめてある。
- 報告の見出し：`## 結果`、`## 根拠・出典`、`## 未確認`、`## 次に必要なこと`、`## 使った書庫の項目`（冒険者は「未確認」の代わりに `## 読めなかったこと`。鑑定士は `## 判定`、`## 合格基準ごとの確認`、`## 指摘`、`## 冒険者に確認してほしいこと`、`## 出典の確認`、`## 成果物を変更していない`、`## 使った書庫の項目`）。
- 呼び出しのメッセージには、入力のパス、合格基準、出力先、ギルドの掟の場所（`guild/.work/codex/default.md`・`project.md`）を毎回書く（サブエージェントは会話履歴を見ない）。
- `plan.json` を書けるのは `guild.py` だけ。受付係は分解結果を `reports/plan-draft.json` に書き、ギルドマスターが `guild.py` の取り込みコマンドで `plan.json` にする。

## agents/*.md の書式

- `name` と `description` を必ず書く（片方が欠けるとスキップされることがある）。`description` は、いつ使うかを具体的に書き、他の役と区別できるようにする。
- frontmatter は `name` `description` `tools` `model` に絞る。プラグインでは `permissionMode` `hooks` `mcpServers` は無視される。
- 本文は役の指示。守らせたい規則は、呼び出しのメッセージでも繰り返す。
- `claude plugin validate` で書式を検査する。

## 受入条件

1. `agents/` に `receptionist.md` `wizard.md` `alchemist.md` `adventurer.md` `appraiser.md` `librarian.md` の6ファイル（司書は書庫の導入で追加：`docs/archive-spec.md`。2026-10-17 の再編で5ファイルから6ファイルになった）があり、各ファイルに `name` `description` `tools` `model` がある。
2. 各役の `tools` が上の表のとおりで、鑑定士・受付係に `Edit` がなく、受付係・錬金術師に Web 系のツールがない（鑑定士は WebFetch のみ。WebSearch と WebFetch の両方を持つのは魔法使いだけ）。
3. 役は進め方の判断（順序・遷移・リトライ）をしない。判断は `guild.py` の出力に従う。
4. 各役の報告が `reports/<目標 ID>-<役>.md` に固定の見出しで残る。
5. 受付係の出力が、`guild.py validate` と `adopt` の計画検査（deliverable が 1 件、`human` に instruction）を通る `plan-draft.json` になっている。書き終える前の自己点検の結果は `brief` に書く。
6. 鑑定士が成果物を書き換えない（指示で禁止し、報告に『成果物を変更していない』と書く）。
7. `skills/quest/SKILL.md` は 500 行未満で、役の詳細は `agents/*.md` に置く。
8. 全役の指示書に、作業の最初に `guild/.work/codex/default.md` と `project.md`（あれば）を読むことが書かれている。`auto` の目標は `class`（`wizard`・`alchemist`・`adventurer`）を持ち、`human` の目標は持たない。
