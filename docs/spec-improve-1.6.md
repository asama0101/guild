# SPEC：guild 改善要望 15 件

## 概要
別環境での試験で出た 15 件の改善要望に対応する。主な変更は、(1) 画面を 1 枚に統合して「ギルドの扉」を 1 回で済ませる、(2) 返事まわりの見せ方（返事済みの強調、全体の一括表示、絞り込み）、(3) 成果物を必ず vault に残す、(4) 設定・使用量・help の追加。

## 変更の中身

### A. 画面（skills/init/board.html に統合。research.html は廃止して削除する）
- 帯のタブ：**使い方（既定）** / **返事が要るもの** / 依頼掲示板 / 研究の記録。切り替えは画面内で行い、フォルダの接続（扉）は 1 回だけ。再読み込み時は、許可済みなら自動で接続する（要望 1）。
- 使い方タブ（既定）：動かし方（init → 画面を開く → /guild:quest、自動実行）・止め方・状態の見方・用語の説明、自動実行の状態（動作中か・間隔・最後の回）、使用量、設定（同時数）を載せる（要望 2・12・13 の画面側）。
- 返事が要るもの（全体）タブ：クエスト・研究・やること・承認を問わず、返事待ちを 1 か所に並べる。絞り込みは「クエスト・研究」で行う（研究を選ぶとそのクエストの質問も含める）。カード見出しに、クエスト番号＋題（研究なら研究番号＋題）を目立つバッジで出す。帯のタブに未返事の件数を赤丸で出す（要望 5・8）。依頼掲示板・研究の記録のタブにも、自分の分の返事欄と同じ絞り込みを付ける。
- 返事済み（受け取り待ち）：同じ位置に残し、緑の枠と「✓ 返事済み（受け取り待ち）」の帯で強調する。カードは薄くして一覧の末尾に寄せ、送り直しはできる。件数の赤丸には数えない。判定は answers/ のファイルから毎回行うので、更新しても同じ見た目になる（要望 4・6・7。7 は現在の仕様どおりで、受け取り後に消える）。
- まとめて送る：送れたものはチェックを外す（個別に送ったものも）。未入力で送れなかったものはチェックを残し、「未入力」を赤字で示す（要望 3）。
- 入力の途切れ：10 秒ごとの描き直しを、内容が変わったときだけにする。入力欄にフォーカスがあるあいだは描き直しを延ばす（返事・評価・計画の直しの欄すべて。IME の変換中も含む）（要望 10）。
- 研究の記録の冒頭：「研究（一覧）」「研究を貼る」「ギルドからの知らせ」を、依頼掲示板と同じように、ページの先頭に横並びで置く（要望 9）。
- ギルドからの知らせ：`stops`（止まっている要因）を赤字で別行に出す。自動実行の最後の回が失敗したときの帯の表示も同じ赤にする（要望 14）。

### B. board.json・requests・各手順（commands/quest.md ほか）
- 同時数：board.json に `max_active`（範囲 1〜8、既定 4）を足す。使い方タブの設定から変更し、requests/ に設定の依頼（`kind: setting`）を置く。ギルドマスターが次の回で取り込む。quest.md の「4 件」はすべて `max_active` に置き換える（要望 12）。
- 知らせ：`notices[].stops[]` を足す。受付嬢の報告書に「## 止まっていること」の節（1 行 1 要因）を足し、ギルドマスターが写す（要望 14）。
- 成果物：達成したクエストは、必ず vault のフォルダに Markdown を残す。研究のクエストは `10_projects/<研究名>/output/`、単発のクエストは `20_quests/<番号> <内容>/output/`（隠しフォルダの `.system` には置かない）。成果物の形が「回答だけ」「おまかせ」（書記が回答だけと決めた場合を含む）でも、結果の全文を Obsidian 用の Markdown として保存し、クエストのノートと `links` からリンクする。既存のノートへの書き足しのクエストも、結果を同じ場所に残す。すでに達成した過去分は、次の `/guild:quest` で board.json の結果から後追いで作る（要望 11）。
- 錠：「run.lock が 1 時間以内なら、自動の回が動いているので止まる。1 時間より古ければ残りなので消してよい」に短くする。待ちは 3 時間から 1 時間にする。commands/quest.md・skills/auto/SKILL.md・skills/auto/guild-run.py（`LOCK_HOURS`）をそろえる（要望 15）。

### C. 自動実行・使用量・help
- 使用量：guild-run.py が `claude -p ... --output-format json` で動かし、各回の入力・出力トークンと概算コストを `guild/.system/logs/usage.jsonl` に追記する。画面は、今日 / 7 日 / 累計を使い方タブに出す。手動の `/guild:quest` の回は数えられないことと、プランの残量は /usage で見ることを画面に明記する（要望 13）。
- `/guild:help`（新しいスキル skills/help/SKILL.md）：動かし方と止め方（自動実行の停止、実行中の /guild:quest の止め方、止まった錠の扱い）を案内し、いまの状態（自動実行の有無・間隔・最後の回、錠の有無、冒険中の件数、返事待ちの件数）を読んで、いま何をすればよいかを伝える。何も書き換えない（要望 2）。

### D. ドキュメントとバージョン
- README・init の報告文を、1 枚への統合・新しいタブ・設定・使用量・help に合わせて直す。`plugin.json` と `marketplace.json` の version を上げる（1.6.0）。

## 受入条件
1. タブを切り替えても「ギルドの扉」が出ない。ブラウザを更新しても、許可済みなら自動で接続する。
2. 開いたとき既定のタブは「使い方」。動かし方・止め方・自動実行の状態・使用量・同時数の設定が見られる。
3. 「返事が要るもの」タブで、クエスト・研究を問わず返事待ちが一覧でき、クエスト・研究で絞れる。カードの見出しで、どのクエストか一目で分かる。
4. 返事を送ると、カードが緑の枠と「✓ 返事済み」で強調され、ブラウザを更新しても同じ見た目になる。件数の赤丸には数えない。
5. 「まとめて送る」を実行すると、送れたもののチェックが外れる。
6. 10 秒の自動更新中も、返事・評価・計画の直しの入力欄に入力でき、IME 変換も途切れない。
7. 研究の記録の冒頭に、研究・研究を貼る・知らせが横並びで出る。
8. 知らせの `stops` が赤字で出る。自動実行の最後の回が失敗したときも赤字で出る。
9. 達成したクエストは、`10_projects` か `20_quests` のフォルダに Markdown の成果物が残る（成果物の形が「回答だけ」でも）。過去の達成分も、次の回で補われる。
10. 同時数を 1〜8 で変更でき、次の回で反映される。範囲外は受け付けない。
11. 錠の古さの判定が 1 時間で、文章が各ファイルでそろい、短くなっている。
12. 自動実行の回ごとの使用量が usage.jsonl に残り、画面に今日 / 7 日 / 累計が出る。
13. `/guild:help` が案内と現在の状態を表示する。
14. 既存のテスト（tests/test_guild_run.py）が通り、`LOCK_HOURS` の変更と usage の記録のテストが足されている。

## 質問せずに決めた 3 件の中身
質問しなかったのは、答えが 1 つに決まる（選択肢がない）か、要望の文面で足りるためです。違うと思う点があれば、「修正あり」のコメントに書いてください。

### 要望 10：返事の入力中に入力できなくなる
- 現状（board.html・research.html で確認済み）：10 秒ごとに `refresh()` が走り、画面を描き直す。返事欄は「質問か返事の状態が変わったときだけ」描き直す作りで、書きかけの文字は引き継ぐ。しかし、描き直しが起きる瞬間に、入力欄のフォーカスとカーソル位置と日本語の変換中の文字が失われる。さらに、クエストのかんばん（評価の欄）と研究のカード（計画を直す欄・評価の欄）は、状態が変わらなくても 10 秒ごとに必ず描き直しており、そのたびにフォーカスが外れる。ご指摘の「途中で入力できないタイミング」は、これが原因と考える。
- 変更後：(1) 各欄に「内容の署名」を持たせ、変わらなければ描き直さない。(2) 入力欄にフォーカスがあるか、日本語の変換中のあいだは描き直しを延ばし、外れたとき（またはフォーカスのない次の周期）にまとめて描く。(3) 描き直すときは、フォーカスのある欄・カーソル位置・書きかけの文字を戻す。対象は、返事・評価・計画の直し・依頼を貼る欄すべて。

### 要望 3：「まとめて送る」のチェックを外す
- 現状：まとめて送ったあと、送れたもののチェックは外れる作りだが、1 件ずつ「返事を送る」で送った分と、未入力で送れなかった分はチェックが残る。ご指摘は、まとめて送ったあとにチェックが残って見えることだと理解している。
- 変更後：まとめて送るを実行したら、送れたもののチェックをすべて外す（個別に送ったものも）。未入力で送れなかったものはチェックを残し、カードに赤字で「未入力」と出す。「全部クリアしてほしい」なら、未入力のものも外すので、そのときはコメントで教えてください。

### 要望 9：研究の記録の冒頭の配置
- 現状：研究の記録は、左の細い列に「研究（一覧）」「研究を貼る」「ギルドからの知らせ」が縦に並び、右に「承認と返事」と選んだ研究が出る。依頼掲示板は、先頭で「依頼を貼る」と「知らせ」が横に並ぶ。
- 変更後：統合した画面の「研究の記録」タブで、先頭に「研究（一覧）」「研究を貼る」「ギルドからの知らせ」を横並びの 3 つで置く（幅が足りないときは折り返す）。その下に「承認と返事」、さらに下に選んだ研究と段の地図を置く（左の列は無くす）。研究が増えて一覧が長くなる場合は、一覧の欄だけ高さを決めてスクロールにする。

## README の更新（必要な範囲）
- 「依頼掲示板と研究の記録（HTML）」の節：2 枚の画面から、1 枚の画面と 4 つのタブ（使い方・返事が要るもの・依頼掲示板・研究の記録）に書き直す。「2 枚は上の帯のタブで行き来できます」を、画面内の切り替えに直す。
- 返事済みの見え方、まとめて送る、絞り込み、同時数の設定、使用量の表示、知らせの赤字を、それぞれ 1〜2 行で足す。
- コマンドの節に `/guild:help` を足す。使い方の流れの図の「board.html を開く」を、新しい画面の説明に合わせる。
- 自動実行の節：錠の待ちを 1 時間に直し、使用量の記録（usage.jsonl）を足す。
- フォルダの節：成果物を必ず `10_projects`・`20_quests` のフォルダに Markdown で残すことを足す。
- `plugin.json` と `marketplace.json` の version は 1.6.0 に上げる。

## 非目標
- Firefox 対応、スマホ表示。
- 手動の `/guild:quest` の回の使用量の集計（セッション記録の読み取り）。プランの残量（5 時間枠・週の枠）の取得。
- 返事の絞り込みの、種類・状態・聞いた役・文字検索（今回は「クエスト・研究」だけ）。
- 過去の知らせの `stops` の後追い。
- vault の外のファイルを読み書きする新しい機能。

## リスク
- 1 枚への統合は変更が大きい（約 1,200 行）。既存の動き（評価・計画の直し・取り消し・優先度）の回帰に注意し、実装後に実ブラウザで確かめる。
- 自動接続は、ブラウザが許可を保持しない設定では効かない（そのときは扉が 1 回出る。統合により、タブ移動では出ない）。file:// での挙動は実機で確認する。
- `--output-format json` の出力の形が Claude Code のバージョンで変わる可能性。取れないときは使用量を「不明」と出し、自動実行は止めない。
- 同時数を増やすと、使用量と鑑定の待ちが増える。
- 錠を 1 時間にすると、1 つの手順が 1 時間を超える回では並走を許す恐れがある（節目で日時を書き直す決まりで緩和する）。
- 過去の達成分の後追いは、board.json の `result`（短い要約）しか材料がないため、全文は残せない。

## 決定ログ

- Q2：返事済みは同じ位置に残し、緑の枠と帯で強調する。
- Q3：すべての達成クエストで Markdown を残し、過去分も補う。保存先は隠しフォルダではなく `10_projects`・`20_quests` のクエスト・研究ごとのフォルダ。
- Q4：同時数は画面で変更（1〜8、既定 4）。
- Q5：自動実行の使用量を記録して、画面（ブラウザ）に出す。手動の回は対象外。
- Q6：錠の待ちを 1 時間にし、文章も短くする。
- Q7：知らせに `stops` を足して赤字にする。
- Q8：「返事が要るもの」は第 3 のタブ。既定にはせず、使い方と説明のタブを既定にする。
- Q9：絞り込みは「クエスト・研究」だけ。
- Q10：help は案内に加えて現在の状態も表示する。
- 要望 10・3・9 は、質問せずに決めた（中身は下の節）。
