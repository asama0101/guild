# SPEC：ボードの作り直し（クエスト掲示板・クエスト進捗のフィルタ・冒険の書とテンプレートの廃止・インプットの選択）

状態：**承認済み**（2026-10-16）
デザイン：https://claude.ai/artifact/42cvmHPA6hwjRJQnqz8bR2 の最下段（「最終案B」の5枚）と、「決定 クエスト進捗」

## 概要
- **目的**：クエストが増えても掲示板が見づらくならないようにする。クエストごとに絞って進捗を見られるようにする。使われていない機能（冒険の書、納品物のテンプレート）を整理する。インプットを、クエストを出すときに既存のものから選べるようにする。
- **ゴール**：下の受入条件を満たし、`python -m unittest tests.test_guild` が通り、ボードをデモ（`?demo=…`）で目視確認できる。
- **方針**：ロジックをシンプルに保つ。`plan.json` と `inbox/` の入力の形は、必要最小限の追加だけにする。外部通信・外部ライブラリなし。

## 変更内容

### 1. クエスト掲示板（掲示板タブの作り直し）
- タブ名を「クエスト掲示板」にする。タブは「クエスト掲示板／クエスト進捗／納品物／書庫／外部サイト／Obsidian／ヘルプ」の7つ（冒険の書を廃止）。
- **左に一覧、右に詳細パネル**（案B）。
  - 一覧：検索、状態のフィルタ（すべて／あなたの番／進行中／受け取り待ち／完了）、行（番号・題名・状態・進捗バー・締切）。完了・中止は既定で畳む。**一覧は既定で表示する。**
  - 「一覧を隠す」ボタンで一覧を隠すと、詳細が横幅いっぱいになる。隠すと、見出し・前後のクエストへ移る「‹ ›」・「何件中何件目」・検索・「＋ 新規」がツールバーに出る。隠した状態は `localStorage` に覚える（使えなければ毎回、表示で開く）。
  - 狭い画面では、一覧と詳細を同時に出さず、切り替える。
  - 「あなたの番が N 件あります」の帯は、今のまま掲示板の上に残す。
- **詳細パネル**：見出し（番号・状態・題名）、あなたの番の手紙、タブ「**道のり／日付／インプット**」。
  - **道のり**：Todo の一覧（状態・予定日・締切は読むだけ）。行を開くと、合格基準と、報告（リンクと抜粋、「パスをコピー」（報告は `.work/` にあり Obsidian には出ないので、「Obsidian で開く」は付けない））が読める。選んだ Todo の合格基準は、画面が広いとき右に出る。
  - **日付**：このクエストのガント（帯＝開始日〜締切、◆＝Todo の予定日、色＝状態、赤い点線＝今日）と、その下に、依頼の開始日・締切と Todo ごとの予定日・締切の入力表。順序の矛盾は赤字の注意（送れる。連動してずらさない）。「変更を送る」「元に戻す」。
  - **インプット**：このクエストが使うファイルの一覧（開く／参照を外す）と、「既存から選ぶ」「アップロード」。
- **手紙**：承認・実行・確認・判断・受け取り・書庫の候補・質問への回答は、これまでと同じ入力を書く。失敗の判断の手紙には、鑑定士の指摘を中に出す。
- **「＋ 新規」ダイアログ**：依頼の内容、開始日（未指定なら今日）、締切（未定なら開始日）、インプット（既存から選ぶ／アップロード。同名は上書きされる旨を表示）。テンプレートの欄はない。
- 「進捗で見る」リンクで、そのクエストだけを選んだ状態でクエスト進捗を開く。

### 2. 廃止するもの
- **冒険の書**：タブ、`talkTab`、`messagesOf` の専用部分、役の絞り込み、吹き出しのスタイルと状態。`plan.json` の `history`・`reports/*.md` は、各役が使うので残す。報告を読む入口は、道のりの行に移す。
- **納品物のテンプレート**：「新規」の選択欄とアップロード、`templates/` フォルダ、納品物タブのテンプレート一覧、`guild.py adopt` のテンプレート検査、`plan.json` の `template`、地図師の指示書のテンプレートの記述、テンプレートに関するテスト。納品物の型は、インプットに付けて依頼文で伝える。
- **日付タブとガント表示以外の掲示板のガント**：作らない（掲示板の「一覧｜ガント」の切り替えは作らない）。

### 3. クエスト進捗のフィルタ
- 「表示するクエスト」ボタン。押すと、検索欄と、スクロールできるチェックリスト（状態ごとに分ける）が開く。選んだクエストはタグで並べ、×で外せる。「進行中だけ」「自分の番だけ」「期限が近い5件」ですぐ選べる。「完了・中止も含める」は今のまま。
- ガントと human の件数は、選んだクエストだけを対象にする。既定は進行中のすべて。選んだ組み合わせは `localStorage` に覚える。

### 4. インプットの選択（自動選択を含む）
- **自動選択**：地図師が、依頼文と `guild/inputs/` のファイルを見て、このクエストに関係するものを選ぶ。
  - `guild.py inputs-list ROOT` を足す。`guild/inputs/` のファイルごとに、名前・拡張子・大きさ・更新日と、文字のファイル（`.md` `.txt` `.csv`）は先頭の数行を返す。
  - 地図師は、この一覧と依頼文を受け取り、文字のファイルは必要なら全文を読んで、`plan-draft.json` に `inputs: [{"name": "…", "reason": "…"}]` を書く。読めないファイル（PDF・Excel・Word・画像）は、名前・更新日・依頼文との対応から選び、理由にその旨を書く。迷うものは選ばず、理由つきで「候補」に回す（`candidates`）。
  - `adopt` は、`inputs` の名前が `guild/inputs/` にあるかを検査する（なければ地図師に差し戻す）。
- **書庫の項目から、インプットへの紐づけ**：書庫の項目に、任意の見出し情報 `inputs`（`guild/inputs/` のファイル名のリスト）を足す。`aliases` と同じ作りのリスト項目として、読み書き・検査（名前の形だけ。存在は検査しない＝上書き・削除で外れても項目は壊れない）・索引に載せる。ボードの書庫の登録・編集欄で、依頼主が付けられる。司書の候補（`archive-draft.json`）の項目にも、任意で `inputs` を書ける（書いた場合は、依頼主の確認を通って登録される）。
- **ヒント（`inputs-list` の `hints`）**：`inputs-list ROOT [--text 依頼文]` は、ファイルごとに `hints`（理由の文字列のリスト）を返す。
  - 依頼文に、確認済み（`confirmed`）か出典あり（`sourced`）の書庫の項目の名前・別名が出てくる（文字の一致、大文字小文字は区別しない、2文字以下の語は除く）→ その項目の `inputs` に挙がったファイルに、ヒント「書庫の用語『KGI』→ このファイル」を付ける。
  - ファイル名、または文字のファイルの先頭の数行に、同じ条件の項目名・別名が出てくる → ヒントを付ける。
  - ヒントのあるファイルを先頭に並べる。地図師は、これを強い手がかりとして使い、最終的な選択と理由を書く。
- **指定したもの**：依頼主が「＋ 新規」で選んだ・アップロードしたファイルは、`request.json` の `inputs`（名前のリスト）に残る。`guild.py new` は、名前が `guild/inputs/` になければ拒否する。
- **`plan.json` の `inputs`**：`[{"name", "source": "user" | "auto", "reason"}]`。指定したもの（`user`）は必ず入り、自動選択（`auto`）が加わる。冒険者・斥候・鑑定士には、この一覧のファイルを渡す。
- **確認と直し**：計画の承認の手紙と詳細パネルの「インプット」タブに、選ばれたファイルを「指定」「自動（理由つき）」の印つきで出す。候補は「追加」で入れられる。自動選択のファイルは「外す」で外せる。
- **新しい入力 `inputs`**：`{"type": "inputs", "add": [名前…], "remove": [名前…]}`。`guild.py ingest` が反映する（名前は `guild/inputs/` にあること。進行中・承認前に受け付け、中止・見直し中は拒否）。履歴に残す。指定した（`user`）ファイルも外せる。
- クエストを出した後に、新しくアップロードして足す操作は、この SPEC の範囲外とする（「＋ 新規」でアップロードする）。

## 受入条件
1. タブが7つで、「掲示板」が「クエスト掲示板」になり、「冒険の書」がない。
2. クエスト掲示板で、一覧が既定で表示される。一覧の行を押すと右に詳細が出る。検索と状態フィルタが動く。
3. 一覧を隠すボタンがあり、隠すと詳細が横幅いっぱいになり、ツールバーに見出し・前後移動・検索・「＋ 新規」が出る。再読み込み後も状態が残る。
4. 詳細のタブは道のり／日付／インプット。道のりの行を開くと、合格基準と報告を読める。日付タブで、依頼と Todo の日付を直して送れる（矛盾は警告だけ）。日付タブにこのクエストのガントが出る。
5. 「あなたの番」の各手紙は、これまでと同じ入力（`inbox/` の JSON の形）を書く。失敗の判断の手紙に、鑑定士の指摘が出る。
6. クエスト進捗で、クエストを選んで絞れる。選んでいないクエストはガントにも human の件数にも出ない。100件あっても操作できる。
7. 冒険の書のコードと、納品物のテンプレート（画面・`guild.py`・指示書・テスト）が残っていない。
8. 「＋ 新規」で、既存のインプットを選んで出せる。存在しない名前は拒否される。アップロードの上書き・バックアップは、今のままである。
9. 地図師が、依頼文と `inputs-list` から関係するファイルを自動で選び、理由つきで `plan.json` の `inputs` に入る。計画の承認の手紙とインプットタブで、指定・自動の別と理由が見え、追加・外すができる。存在しない名前は `adopt` と `ingest` で拒否される。
10. 書庫の項目に `inputs` を付けて保存でき、`inputs-list --text` が、依頼文に出てくる項目の名前・別名から、紐づいたファイルにヒントを付けて先頭に並べる（推測の項目・2文字以下の語・廃止の項目は対象外）。
11. 外部通信・外部ライブラリを使わない。`tests/test_guild.py` が通る（ボードの文字列の契約テスト、テンプレート関連のテスト、README・docs・指示書の契約テストを新しい構成に直す）。

## 非目標
- 掲示板の中のガント表示（日付タブのクエスト別ガントと、クエスト進捗で足りる）。
- 他のデザイン案（カンバン・貼り紙・日別・レーン・集中モード）。
- クエストを出した後の、新しいファイルのアップロード（既存ファイルの追加・外すは範囲内）。
- 管理者の直しから学んで、書庫の項目に自動で紐づけること（次の版）。
- PDF・Excel・Word の中身を読んで関連を判断すること（名前・更新日・依頼文からの判断に限る）。
- 並べ替えの保存、複数クエストの一括操作。
- `plan.json` の形式の変更（`template` の削除と、`inputs` の追加を除く）。

## リスク
- `board.html` の掲示板まわり（`boardTab`・`composer`・`questToc`・`questDetail`・手紙の描画）は大きい。→ 手紙・入力の関数は変えず、置き場所だけ移す。
- 実ブラウザの `.work` 読み込み（前回から未確認）は、この改修の確認と一緒に、依頼主に手元で確かめてもらう。
- `localStorage` は、デモや一部の環境で使えない。→ 使えなくても動くようにする。
- テンプレートの廃止は、すでに入れた機能（SPEC 2026-10-15 のQ11）の取り消しで、`guild.py`・テスト・docs・指示書に及ぶ。→ 一括で削除し、旧テストも直す。
- 左の一覧を隠した状態と、狭い画面での切り替えが重なると、状態が分かりにくい。→ 狭い画面では隠すボタンを出さず、一覧と詳細を切り替える。

- 自動選択の精度：中身を読めないファイルは、名前と更新日が頼りで、外れる・漏れることがある。→ 理由を出し、承認の前に依頼主が追加・外すで直せる。選ばなかった候補も見せる。
- 短い語や一般的な語による偽の一致。→ 一致の対象を確認済み・出典ありの項目に限り、2文字以下の語は除き、理由を画面に出す。
- `inputs-list` の先頭行に、秘密情報が含まれうる。→ 地図師にだけ渡し、画面には出さない。
