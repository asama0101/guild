# 書庫（archive）実装計画

> 実装者向け：チェックボックスの順に進める。各タスクは、テスト → 実装 → 通ることの確認 → コミット。

**Goal:** `guild/knowledge/`（依頼別ログ）を、種類別・1項目1ファイルの `guild/archive/`（書庫）に置き換え、全役が索引から読み、使った項目を報告に書く。

**Architecture:** 決定的な処理（検査・重複検索・ファイル書き込み・索引の再生成）は `guild.py`、抽出は新しい役 司書（`agents/librarian.md`）、確認と手入力はボード。依頼完了後、司書が `reports/archive-draft.json` に候補を書く → `guild.py archive-propose` が検査して心得を登録、残りを `archive.json` に「提案中」として残す → ボードの手紙で依頼主が選ぶ → `inbox/` の `archive` 入力を `ingest` が反映する。手入力・昇格・廃止は `archive/inbox/` の JSON を `guild.py archive-ingest` が反映する。

**Tech Stack:** Python 標準ライブラリ、unittest、素の HTML/JS（board.html）。

**Spec:** `docs/archive-spec.md`

## Global Constraints
- 保存先は `guild/archive/` の Markdown。DB・外部サービスは使わない。
- 種類は term / flow / fact / lesson。フォルダは `terms/ flows/ facts/ lessons/`。
- 確度は confirmed（確認済み）/ sourced（出典あり）/ guess（推測）。
- 項目の見出し情報：`name` `type` `aliases` `confidence` `source` `confirmed` `status`（active/要確認/廃止）`summary`。
- 廃止は削除せず `status: 廃止`。索引は active と 要確認 だけを載せる。心得（lesson）は索引に載せない（役は読まない）。
- 候補は1依頼あたり12件まで。
- 日本語のコメント・メッセージ（既存の慣習）。

## Review Focus
- 同名・別名（大文字小文字違い）の候補 → 新規でなく更新になる。
- 項目名に `/ \ : * ? " < > |` や空白、`..` を含む → ファイル名に使える形に直し、`archive/` の外へ書かない。
- 中止（aborted）された依頼の提案への回答も反映できる（`apply_input` の中止判定より前で処理する）。
- 提案を2度送られても二重に登録しない。
- 破損した JSON・不明な type が `archive/inbox/` に来ても、全体を止めず rejected に移す。
