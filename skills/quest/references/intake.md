# 取り消しと資料（手順 2・4 から）

## 取り消し（`requests/C<日時>.json`、`kind: cancel`。`target` はクエスト番号か研究番号、`reason`）
手順 2 の最初に扱う。
- クエスト：`達成`・`中止` でなければ `中止` にし（`log` に理由）、`board.py close-questions --quest <id> --answer 取り消し` で未回答の質問を閉じる。そのクエストを前提にしているクエストは `返事待ち` にし、伝令の取り次ぎで「前提なしで続ける／やめる」を聞く（`["前提なしで続ける", "やめる"]`）。作業中のギルド員は呼ばず、報告書も鑑定もしない。
- 研究：研究を `中止` にし、その研究のクエストのうち `達成`・`中止` でないものを全部 `中止` にする。承認や研究の質問も `close-questions --study <id>` で閉じる。研究ノートの `guild_status` も `中止`。
- 取り消したことは締めの知らせに入れる。

## 資料（添付ファイル・URL）
- 画面で添えたファイルは `guild/.system/requests/files/R<日時>/` に入っている。受付のときに、その依頼の研究かクエストの `input/` に移す。
- Word・Excel・PowerPoint（.docx .xlsx .pptx）は、移したあと `<venv_python> -m markitdown <ファイル> -o <同じ名前>.md` で Markdown の写しを `input/` に作り、ギルド員には写しを読ませる。`venv_python` は board.json にある（無ければ Office の変換は使えない扱い）。MD・TXT・CSV・PDF・画像はそのまま読ませる。
- `markitdown` などの道具が無くて止まるときは、`python -m pip install "markitdown[all]"` で入れてよいかを伝令の取り次ぎ（手順 6）で質問に載せる。単発のクエストなら、その資料を使うクエストを `返事待ち` にする（受付で止まったなら遷移表の「（新規）→返事待ち」。仕分けのあとなら「受付済→返事待ち」）。研究の資料なら、研究は `計画中` のまま、`study_id` 付きの研究の質問で聞く。「入れてよい」の返事が来たら入れて写しを作る。
- 依頼 JSON に `urls`（任意。1 行 1 件の参考 URL。quest・study 共通）があるときは、`add-quest`・`add-study` にそのまま載せ、依頼書に URL を書く（画面が http(s) 以外を貼る時に除くので、ここへ来る `urls` は http(s) のみ）。
- 冒険者には、各 URL から同一ドメインの中だけでリンクをたどらせる。範囲は board.json の `crawl_depth`（1〜5）と `crawl_limit`（1〜100。取得ページ数の上限）。キーが無ければ 2 と 20 とみなす。
- 取得物は `input/` に Markdown で保存させる。
- 冒険者の報告書には、取れなかった URL（認証が要る・失敗）と、上限で打ち切って残った未取得リンクの数を書かせる。
- ギルドマスターは、取れなかった URL と未取得リンクの数を依頼主への知らせ（締め）に入れ、「手動でダウンロードして資料に添えてください」と案内する。
