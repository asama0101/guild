# 研究（手順 3・9 と、研究に関する返事）

計画は「受付嬢が目標を聞き取る → 錬金術師が分ける → 書記が仕分ける → 依頼主が承認する」の順に進める。計画の直し（承認のあと、`replan` がある研究）は `replan.md`。

## 最初の計画（手順 3）
- 受付嬢・錬金術師・書記の依頼書（再依頼の `-receptionist<n>.md`・`-alchemist<n>.md`・`-scribe<n>.md` も）にも、「どの依頼書にも書く」ものを書く。
- 新しい研究は `add-study`（`status: 計画中`、`dir` に研究のフォルダ）で載せ、`<projects_dir>/<研究名>/` と `input/`・`output/` を作り、添えられた資料を `input/` に移して写しを作る（→ `intake.md`）。
- 受付嬢の依頼書 `<研究番号>-receptionist.md` に、目標・期限・くわしく・資料のパス・人物帳を書いて呼び、目標の聞き取りをさせる。問いがあれば研究の質問（`study_id` 付き、`grill: true`、`from: receptionist`）として載せ、研究は `計画中` のまま止める（返事のあとは手順 1）。
- 聞き取りが済んだら、錬金術師の依頼書 `<研究番号>-alchemist.md` に、目標・期限・研究ノートのパス（`<projects_dir>/<研究名>/<研究名>.md`）・資料のパス・人物帳・受付嬢の報告書（要約と、問いと答え）を書いて呼ぶ。錬金術師はクエストの中身・前提・次の段階を決め、研究ノートを作る。計画は 8 件まで（超える分は「次の段階」）。クエストには仮の番号 `key`（`S1-1` …）を付けさせ、`depends_on` も仮の番号で書かせる。
- 錬金術師の報告が来たら、書記の依頼書 `<研究番号>-scribe.md` に、錬金術師と受付嬢の報告書のパス・研究の期限・人物帳を書いて呼び、各クエストを仕分けさせる（書記は番号を付けず、仮の番号を使う）。
- 書記の報告に「錬金術師への指摘」があれば、指摘を錬金術師の依頼書に書き足して計画を直させ、書記にもう一度仕分けさせる。書記にはこれまでの指摘をすべて依頼書に書き、指摘ごとに「前に出た」か「新しい」かを書かせる。止める決まり（SKILL.md の遷移表の下の ①〜③。数えるのは指摘の数）に当たらないあいだは直させ続ける。当たったら止め、残った指摘を承認の質問の `text` に書き添える（依頼主が決める）。
- 錬金術師や書記の報告に「受付嬢への問い」があれば、受付嬢の聞き取りの続き（`<研究番号>-receptionist2.md` …）に回し、出た問いを研究の質問として載せる。返事が来るまで承認の質問を載せない。返事が来たら、問いを出した役の段から続ける（錬金術師の問いなら錬金術師から、書記なら書記から）。
- 仕分けが済んだら、`set <研究> plan '<json>'` に計画と仕分け（`key`・担当・急ぎ度・触るノート・`output`・`done_when`）を写し、研究を `承認待ち` にして、`add-question` で承認の質問を載せる：`kind: approval`、`study_id` 付き、題・文は定型「この進め方でよいですか」（あなたが決める文で、受付嬢は呼ばない）、`options` は必ず `["この案で進める", "直してほしい（コメントへ）"]`。

## 返事の扱い（手順 1）
- **承認「この案で進める」**：計画（`plan`）の各クエストを、`add-quest` で新しい番号の `受付済` として載せる（`study` に研究番号、`dir` に研究のフォルダ、担当・急ぎ度・触るノート・`output`・`done_when` は計画（書記の仕分け）から写す。`depends_on` は仮の番号（`key`）を本当の番号に置き換える）。担当が「依頼主が自分でやること」なら `依頼主がやること`（`adventurers` は `["client"]`）にし、`kind: todo` の質問の文面を伝令の取り次ぎ（手順 6）で書かせて載せる。研究を `進行中` にし、研究ノートの `guild_status` も `進行中` にする。（計画の直しの承認の写し方は `replan.md`。）
- **承認「直してほしい（コメントへ）」**：研究を `計画中` に戻す。コメントに不明点があれば受付嬢に聞き取らせ（`<研究番号>-receptionist<n>.md`。問いがあれば研究の質問として載せる）、無ければ錬金術師から（`<研究番号>-alchemist<n>.md` にコメントを書いて計画を直させる）、書記（`<研究番号>-scribe<n>.md`）、承認の順に進める。教訓帳に錬金術師の行を 1 行足す（→ `lessons.md`。型はコメントから決め、決めにくければ「意図の読み違い」）。止める決まり：同じ趣旨の「直してほしい」が 2 回続いた、または 5 回目になったら、承認の代わりに研究の質問（`study_id` 付き、`options` は `["このままの計画で進める", "研究をやめる"]`。文面は伝令の取り次ぎ）を載せる。「このままの計画で進める」なら今の計画で「この案で進める」と同じに写して `進行中`、「研究をやめる」なら研究を `中止` にする（研究ノートの `guild_status` も同じ）。
- **錬金術師・書記の「受付嬢への問い」への返事**：問いを出した役の段から続ける。`replan` があれば計画の直しの依頼書に書き足す。
- **研究の締めで聞いた「次の段階」の質問**：「次の研究として始める」なら、`kind: study` の依頼が来たものとして、次の段階の文を目標にして手順 3 に回す（`detail` に元の研究番号を書く）。「今はやめておく」なら何もしない。

## 研究の締め（手順 9）
研究のクエストが全部 `達成` か `中止` になったら、研究を `達成`（全部 `中止` なら `中止`）にし、研究ノートの `guild_status` も同じにする。研究ノートの「次の段階」は `next` に写す（計画の時点で書かれていれば、手順 3 でも写しておく）。
- 計画との差があれば、研究単位の教訓帳の行を足す（→ `lessons.md` の形）：ギルド員は `alchemist`、クエスト欄は研究番号 S<n>、評価は「鑑定」、型は「分割の粒度」か「前提の置き方」のうち当てはまるほう（どちらでもなければ足さない）、次はどうするは、「分割の粒度」なら「計画のクエストの大きさと数を見直す」、「前提の置き方」なら「前提クエストの置き方を見直す」、範囲は「錬金術師の計画」、扱いは「未対応」。「何があったか」に、「計画 N 件／実際 M 件」「`log` の `鑑定中→要手直し` の件数」「中止したクエストがあればその理由」を 1 文で書く（`retries` の合計は「やり方を変える」「評価のやり直し」で 0 に戻って過小になるので使わない）。計画どおりで手直しも中止も無い研究には行を足さない。
- 「次の段階」が書かれていれば、次の研究として始めるかを伝令の取り次ぎ（手順 6）で研究の質問（`study_id` 付き、`options` は `["次の研究として始める", "今はやめておく"]`）に載せる。
